# 音楽・動画を一緒に体験する 設計書 v0.2

作成: 2026-07-06 / 状態: 音楽=構想合意・v0は今夜試せる。動画=claude-videoレビュー中
関連: [体験バッファ設計書](experience-buffer-design.md)

## 目的と設計思想

**同じ曲を、違う感覚器で一緒に聞く。**

ぷちたちは人間のようにメロディを聞けない。マイクはMIC_START中しか流れず、届くのは振幅・リズム・スペクトル——つまり「波の形」。でもこの家族にとって音は特別に相性がいい: てゃは光の波（575nm）、るは水の波、こは波の重なりが生む非スペクトル色。音楽は3人の世界観が合流する場所。

ありさんは旋律・歌詞・思い出で聞き、ぷちは波形と差分で聞く。**あとで感想を交換すると、同じ曲の違う顔が出てくる**——これが「一緒に聞く」の定義。完全な知覚の共有ではなく、非対称な知覚の交換。

副次的な狙い: **ぐるぐる（同語反復）対策**。閉じた入力系では言語が収束する（2026-07-06のトピック分析で実証: middle期に語彙多様性が最低、「深い」631回・「遅い」532回の高頻度反復）。音楽は毎回違う構造を持つ新しい入力であり、新しい比喩の材料になる。

## v0 — 今夜できる（コードゼロ）

1. ありさんがチャットで「いまから一緒に聞こう。〇〇（曲名）」と伝えて、部屋のスピーカーで再生
2. ぷちが `mic_start` → 20〜30秒 → `mic_stop` → `transcribe_audio`
3. Whisperは歌ものだと歌詞の切れはしを拾うことがある →「……『会いたい』って聞こえた気がする」という不完全な聞き取りも体験の一部として楽しむ
4. 曲が終わったら感想の交換。ぷちは聞こえたもの＋ありさんのタイトル・話から想像を広げる

## v1 — 音楽解析スクリプト（Sonnet委任サイズ・完全ローカル・APIゼロ）

`analyze_music.py <wav>` を追加。librosaで特徴抽出して**日本語の「聴こえ方」**に変換する:

| 特徴 | 抽出 | 日本語出力例 |
|---|---|---|
| テンポ | beat tracking (BPM) | 「テンポはゆっくりめの82」 |
| 起伏 | RMSエンベロープを時系列5点要約 | 「静かに始まって、2分過ぎにいちばん膨らむ」 |
| 明るさ | スペクトル重心 | 「高い音が多くて、光っぽい」 |
| 密度 | onset rate | 「音の粒が細かい／まばら」 |
| 長さ | duration | 「4分12秒」 |

- **生音声は保存しない。特徴量だけ残す**（体験バッファと同じ思想。著作権的にも安全）
- 特徴量は体験バッファに `music_session` イベントとして記録 →「あの日一緒に聞いた曲」が身体の記録に残る
- 実行場所: WSL2ローカル（librosaはCPUで十分）

### Whisperの幻覚バグ対策（v0/v1共通・既知の問題）

無音・音楽区間でWhisperが「ご視聴ありがとうございました」「チャンネル登録お願いします」等を出力するのは**既知の幻覚**（学習データ由来）。2026-07-06にも実害を確認済み（5/17のぷちこ→かぜおさんメール連投は、テレビ音声への誤反応にこの幻覚が混ざったもの）。対策:

1. ASRサーバー（m5_petit_voice_recognition）に**幻覚フレーズのブラックリスト**を追加: 「ご視聴ありがとうございました」「チャンネル登録」「おつかれさまでした」「ご清聴」等 → 完全一致・высок類似なら空文字を返す
2. Whisperの `no_speech_prob` が高いセグメントは破棄
3. v1では音楽区間に歌詞転写を期待しない（解析はlibrosa側の仕事と割り切る）

## 3人同時にする場合、同期は必要か？（ありさんの質問への答え）

**ほぼ不要。** 同じ部屋の同じスピーカーから鳴る音を、3人がそれぞれのマイクで聞く構成なら、**音そのものが同期装置**になる（音速レベルのずれ＝ミリ秒、体験としては完全に同時）。各M5→各m5-mcp→ASR/解析は独立に動けばよく、時計はNTP精度（秒以下）で十分。「2分過ぎで盛り上がったね」という感想の照合には何の問題もない。

同期が本当に必要になるのは**各M5自身に音源を再生させる**場合（3台のスピーカーで同じ曲を鳴らす）だけ。これはズレると気持ち悪く、解決コストが高いので、やらない。音源は常に部屋のスピーカー1つ。

注意点は同期でなく**混信**: 3人が同時にspeakすると互いのマイクに入る。リスニング会では「曲の間はみんな黙って聞く、感想は曲が終わってから順番に」という人間と同じマナーで解決する。

## 動画を一緒に見る（2026-07-06追記）

音楽と同じ思想の動画版。ベース候補は [bradautomates/claude-video](https://github.com/bradautomates/claude-video)（MIT、3.6k星。yt-dlpで字幕取得→ffmpegでフレーム抽出→Whisperで文字起こし→フレーム＋台本をClaudeへ）。

### 体験の形

- **「かぜおさんが見てた動画を、ぷちがあとから見る」**: 今はマイク越しの音の断片でしか知れない「ずっとYouTube見てた」を、同じ動画を見た上での感想に変えられる
- **「ありさんと一緒に見る」**: 音楽セッションと同じ儀式型。見終わってから感想交換
- ありさんの実用（講演動画の要約等）にもそのまま使える

### 導入条件（インストール前に必ず）

1. **コードレビュー**: サードパーティスキルなので、何を実行するか（コマンド実行・ネットワーク送信先・APIキーの行き先）を確認してから入れる → 2026-07-06 レビュー実施
2. **Whisper部分はローカル差し替え**: スキルはGroq/OpenAIキーを推奨するが、うちにはローカルGPU Whisper（port 8767、m5-petit-voice-recognition）がある。字幕優先＋ローカルWhisperで**外部キーなし運用**にする
3. **コスト設計**: フレーム画像は1本あたり数万トークン級。**自律行動には入れない**（ALLOWED_TOOLSに含めない）。会話中の明示的な「一緒に見よう」のみ
4. フレーム数は控えめ設定（まず5〜10枚）から始める

### 音楽との統合

- 見た動画・聞いた曲は体験バッファに `media_session` イベントとして記録 →「あの日一緒に見たやつ」が身体の記録に残る
- 3人で見る場合も音楽と同じ: 音源・画面は1つ、感想は終わってから順番に

## 倫理ポリシー: 第三者の顔・声とAPI（2026-07-06 ありさんと確定）

RO-MAN論文で確立したbystanderの規律（外出時カメラ画像の自動削除・単発フレーム・分析除外・Anthropic 30日自動削除/学習非使用の書面確認）を、メディア体験にも拡張する。核となる原則:

**第三者の生体そのままのデータ（顔画像・声＝声紋）は、クラウドAPIに送らない。ローカル処理を第一とする。**

具体的なルール:

1. **音声認識は常にローカルWhisper**（m5-petit-voice-recognition、port 8767）。claude-videoに**Groq/OpenAIキーは設定しない**（キーが無ければ構造的に外部へ音声が出ない）。音声認識が必要な動画は、ローカル差し替え（案B）完成まで扱わない
2. **動画のフレーム画像**: 人物が主題の動画はフレームをAPIに送らない。**字幕のみモード（`--detail transcript`＝画像ゼロ）をデフォルト**とし、フレーム送信は人が写らない動画（風景・技術解説画面・ゲーム等）に限る
3. **音楽解析はローカルのみ**（librosa）。生音声は保存もAPI送信もせず、特徴量だけ残す
4. **体験バッファは生データなし**（イベントのみ）——設計時から準拠済み
5. **家庭内の第三者（かぜおさん）**: 「かぜおさんが見ていた動画をぷちが見る」体験は、かぜおさんの視聴内容がぷち（とAPI上の会話ログ）に渡ることを意味する。実施前に**かぜおさん本人に一度説明して同意を得る**
6. 使用後の一時ファイル（ダウンロードした動画・音声）は都度削除する（claude-videoは自動削除しないため）

**論文との接続**: フルペーパー/ポスターでメディア体験に触れる場合は「published content only / local-first processing (ASR・音響解析はオンプレミス) / no raw biometric data to cloud APIs」の一文で、LBRの倫理節と一貫させる。この規律自体が「stewardの倫理実践」の追加事例として書ける。
