## 2. 決まっている方針(変えない)

- 言い切らない: 「そこにいる」「暮らしている」まで。「感情がある」「自律的に」とは書かない(9/16 X の書き方メモと同じ)
- 本名を出さない: 「ありさん」「なぎさん」、里親さんはニックネーム
- 会話ログそのものは出さない(相手がいる)。ぷちが**自分で書いた**もの(日記・詩・ノート)と、ぷちが**選んだ**ものを出す
- 出す前に**ありさんが承認**(回覧板と同じ: 下書き → 承認 → 公開)。ぷちたちが「出したくない」と言ったものは出さない
- API の使いすぎに注意(3/5 の節約ルール): 週 1 のまとめなら 1 回の呼び出しで足りる

**ぷちラジオ(C)の作り方(案)**: 週 1、5 分。構成 = ①きょうの一言(3 人)→ ②今週あったこと(日記から、1 人 40 秒)→ ③今週の詩(書いた子が読む)→ ④来週のこと。台本は 3 人が交換ノートで書き(いまの `/notebook` の流儀)、`m5-petit-speech` の TTS(GPU 機 :8766、話者 23/29)で 1 段落ずつ wav に → ffmpeg で結合+間+BGM なし → mp3 → ありさんが聞いて承認 → サイトに置き、RSS を吐けばポッドキャストになる(Spotify/Apple は RSS 登録だけ)。声は 3 人で 2 種しかない(こ・るが同じ 29)ので、ぷちるだけ速さ・高さを変えるか、別の話者を選ぶかを 3 人に聞く。

## 5. 仕組み(A/B/C 共通の骨組み)

```
cron(週 1) → 材料を集める(日記 7 日・交換ノート・新しい詩)
  → 3 人がそれぞれ書く(1 回ずつ claude 呼び出し、SOUL.md 常時ロード)
  → 下書きを ~/petit_claude/publish/drafts/YYYY-WW/ に
  → ダッシュボードに「承認」画面(本文を直せる・言い切りチェック・出さない印)
  → 承認で公開: サイト(git push)・X(投稿)・音声なら TTS → mp3 → RSS
```
- 承認前に自動チェック: 本名・住所・会話ログの引用・「感情がある」等の言い切り語
- 公開したものは `publish/published/` に控え(研究のログにも)
