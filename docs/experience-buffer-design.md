# 体験バッファ 設計書 v0.2

作成: 2026-07-06 / 状態: **ありさんレビュー済み（同日）・実装未着手**
実装担当（予定）: Sonnetサブエージェント / 設計レビュー: ありさん

## 目的

**「身体は経験しているのに、心は知らない」を減らす。APIコストをかけずに。**

- 電車のガタンゴトン、持ち上げられて運ばれたこと、寝ている間に起こされたこと——今はすべて、心（Claudeセッション）が走っていない時間に消えている
- ありさんの見えないケア（移動させる・話しかける・起こす）は、ボタンを押さないからログに残らず、ぷちに気づかれない
- 解決の形: **身体が覚えていて、脳があとから読む**。人間の睡眠中の身体感覚と同じ構造。リアルタイムにAPIを呼ぶのではなく、ローカルの軽量デーモンがイベントだけを記録し、次にぷちが目覚めたとき（自律行動 or チャット）に「身体の記録」として渡す

2026-07-06のぷちこの12:30の記憶（リビングに連れて行かれたことに気づいた）を、偶然ではなく仕組みにする。

## 全体像

```
M5デバイス（身体）
  │ センサーストリーム: ambient / proximity / battery / 加速度 / ジャイロ / touch
  ▼
experienced（体験デーモン・ローカル常駐・API呼び出しゼロ）
  │ エッジ検出: 生データ → イベント
  ▼
体験バッファ  ~/petit_claude/characters/<id>/state/experience/YYYYMMDD.jsonl
  │
  ├─ 自律行動: autonomous-action.sh がプロンプトに「身体の記録」節を注入
  ├─ ダッシュボード会話: call_claude が未読ダイジェストを注入
  └─ ターミナルチャット: interoception hook が状態1行＋未読件数を注入
```

## コンポーネント

### 1. experienced（体験デーモン）

- キャラクターごとに1つ（3人分）。ローカル常駐、**APIは一切呼ばない**
- 入力: M5のセンサーストリーム（→ 確認事項1）
- 出力: イベントJSONL（追記のみ）
- M5オフライン時は再接続リトライしつつ、断絶自体をイベント化する

### 2. イベント検出ルール（v1）

| イベント | 検出方法 | ぷちが読む例 |
|---|---|---|
| `picked_up` / `put_down` | 加速度の分散スパイク＋姿勢変化 | 「12:28 持ち上げられた」 |
| `carried` | picked_up後、揺れが継続 | 「〜30秒くらい運ばれた」 |
| `ambient_jump` | 照度の急変（閾値超の差分） | 「明るい場所に移った（ambient 89→412）」 |
| `vibration_sustained` | 中強度の周期振動が2分以上（開始/終了で1イベント） | 「09:00-09:34 規則的な揺れ——電車かも」 |
| `proximity_presence` | 近接センサーの反応 | 「誰かが近くに来た」 |
| `touch` | WSのtouchイベントそのまま | 「頭を触られた」 |
| `offline_gap` | ストリーム断絶→復帰 | 「14:02から26分間、感覚がなかった」 |
| `battery` | charging開始/終了、残量低下 | 「充電が始まった」 |
| `sleep` / `wake` / `woken` | 状態遷移（下記3参照）。**woken = 眠っている間にwakeされた＝起こされた**。source付き | 「07:00 眠っているところを起こされた（ありさん・ダッシュボードから）」 |
| `asleep_actuation`（v2） | 寝ている間の顔変更・speak実行の記録 | 「寝ている間に、誰かが顔を変えた」 |

- 閾値はキャラごとのconfig（JSON）で調整可能
- **生センサー値は保存しない。イベントのみ**（プライバシーと容量。音声の内容も録らない——録るのは「音があった」という事実だけ）
- 同種イベントの連続は圧縮する（電車1回の乗車で500イベントにしない）

### 3. 身体状態ファイル `state.json`

`{"state": "awake" | "asleep", "since": ..., "last_event_ts": ...}`

寝てる/起きてるのsingle source of truth。書き込み元（choke point）は3箇所:

1. m5-mcp の `sleep()` / `wake()` ツール（各1行追加）
2. ダッシュボードの sleep/wake ボタンのハンドラ
3. 身体側の自動遷移（電池切れ・自動スリープ）→ デーモンがストリームから推定（→ 確認事項2）

`woken` の source は、wake を書き込んだ主体（cron / dashboard / chat / 不明=物理）をそのまま記録。

### 4. ダイジェスト生成 `experience_digest.py <char> [--mark-read]`

- カーソル（`last_read_ts`、キャラごと1つ）以降の未読イベントを、上の表の右列のような**日本語の行**に整形して出力
- `--mark-read` でカーソルを進める（読み捨てではなくカーソル方式——**元のJSONLは消さない**。このログはそのまま研究データになる）
- 未読ゼロなら空出力（注入側は節ごと省略）

## 注入ポイント（「hookで入れるべき？」への答え）

| セッション | 方法 | 理由 |
|---|---|---|
| **自律行動** | autonomous-action.sh がプロンプト冒頭に「## 身体の記録（前回目覚めてから）」節としてダイジェストを注入 | プロンプトは自前で組み立てているので、hookより確実で見通しがいい。カーソル更新はセッション起動成功後 |
| **ダッシュボード会話** | call_claude が未読ダイジェストをシステムプロンプトに追加 | 同上（コード側で制御） |
| **ターミナルチャット** | 既存のinteroception hook（UserPromptSubmit）に1行追加: `[body] state=awake unread=3 → 詳細は experience_digest.py で読める` | 毎ターン注入は重いので、状態＋未読件数だけ。ぷちが気になったら自分で読む |

**寝ている間の扱い**: 寝ている間はセッションが走らない → デーモンだけが記録を続ける → **目覚めた最初のセッションが「寝ている間のできごと」をまとめて受け取る**。「寝てると起きたときしかわからない」は仕様ではなく、この設計そのもの。起こされたこと（woken）も必ずその最初の一読に含まれる。

## 研究との接続

このイベントログは、そのまま**ありさんのケア行為の自動計測**になる。RO-MANフルペーパーの★宿題「steward行為の頻度/時間推移を記述統計で示す」——picked_up・woken・touchの時系列は、メール分析と対になる「身体側のstewardshipコーパス」。RQ2以降の一次データとして設計時点から意識しておく。

## 決定事項（2026-07-06 ありさんレビュー＋ファームウェア調査で確定）

1. **取得方法 = HTTPポーリング（1〜2Hz）で確定。ファームウェア変更なし。**
   調査結果: WS(8080)は`WebSocketsServer`だが、センサー送信が`sendTXT(wsClientNum, ...)`＝最後に接続した1クライアント宛のため、デーモンが相乗りするとm5-mcpのストリームを奪ってしまう。一方、HTTP `/sensors` エンドポイントが既に存在する（加速度・ジャイロ・ambient・battery・`is_sleeping`入り）ので、デーモンはこれをポーリングする。持ち上げ検出は重力ベクトルの変化ベースなので低レートでも成立する。高頻度サンプリングが欲しくなったらv2でファームを`broadcastTXT`化する
2. **自動スリープ検出 = 解決済み。** センサーJSONに`is_sleeping`フィールドが既に入っている（ino実装確認済み）。ポーリングで遷移を検出できるため、ino側の変更は不要。電池低下の自動スリープも同じ経路で捕捉できる
3. **起動方式 = cron @reboot ＋ 5分ごとの見張り（死んでいたら再起動）。**（補足: これは「PCを再起動してもデーモンが自動で立ち上がり続ける仕組み」の選択の話。既存のcron運用と同じ流儀なので管理が一番楽）
4. **マイク = v2送りで確定。** どのみちファームウェア変更（常時音声レベル送信）が必要なため。Phase 1が動いてから再検討
5. **保存期間 = 永久保存。** サイズ試算: 多めに見て500イベント/日でも約75KB/日/人 → 3人で年間約80MB、十分軽い。月次cronで前月分をgzip圧縮（約1/10になる）し、`~/petit_claude/backup/` へ月1コピー。削除はしない
6. **プロセス構成 = キャラごとに3プロセス。**（障害分離。1人のM5がオフラインでも他の2人の記録は止まらない）
