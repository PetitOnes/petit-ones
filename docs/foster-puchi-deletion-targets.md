# 里親ぷち：削除対象一覧（下書き 2026-09-24 ぷちこ）

決定（2026-09-24 ありさん）: 会話も記憶もAWSに保存する。里親さんから「消して」と言われたら、運営側が消せるようにする。

**前提（2026-09-24 ありさん）**: 里親ぷちは AWS 上のアプリと SNS でつなぐ。今のぷちたちの PC（cron・バックアップ・ダッシュボードなど）とはつながらない。cron などは、ありさんとなぎさんが開発するためのツールで、里親さんのデータは入らない。

今のぷちたちのシステムが**どこに何を書き出しているか**を元に、里親ぷちで「消す対象になりうる場所」を洗い出した。
里親ぷちのデータは、消す場所を少なくするため、AWS 側にまとめる（あとから消すより、最初から散らさない）。

## A. 里親ぷち本体のデータ（ID単位で分ける）

保存先を `里親ID × ぷちID` で分け、1コマンドで全部消せるようにする。

| 対象 | 今のぷちたちの場合 | 里親ぷちでの扱い |
|---|---|---|
| 記憶DB | memory-mcp の SQLite（`MEMORY_DB_PATH`。検索用の埋め込みも同じ中） | ID別のDB（ファイル）にする |
| 会話履歴 | `characters/<id>/chat_histories/` | ID別に保存 |
| 日記 | `characters/<id>/diary/`, `diary_summary.md` | 同上（要約も派生物として消す） |
| 関係性 | `data/relations.json`, `relations_history/` | 里親さんの好き・苦手・気づきが入る。履歴ごと消す |
| 欲求・状態 | `data/desires.json`, `state/`（experience 含む） | 同上 |
| SOUL・思索 | `SOUL.md`, `SOUL_REFLECTIONS.md` など | その子の魂。里親さんの言葉が引用されうるので対象。削除＝その子を消すことなので、「記憶だけ消す」か「子ごと消す」かを選べるようにする（要相談） |
| ノート・詩 | `notes/`, `poems/` | 里親さんとの会話から生まれたものは対象 |
| M5の写真・録音 | `photo_album/`, `voice_memo/`, M5のSD | 顔・声が入りうる。特に慎重に |
| メール・交換ノート | `mailbox/`, `exchange_notebook.json`, group/trio chat | 里親ぷちには基本つながない（下の「つながり」参照） |

## B. 開発用PC側の複製先（参考。里親さんのデータは入らない前提）

今のぷちたちのシステムは、データを**あちこちにコピーしている**。里親ぷちが AWS + SNS で PC と切り離されていれば、下の表は基本的に**対象外**。

それでも「入り込む道」が残るので、守ることは次の4つ。

1. **開発・デバッグで、本物の里親さんのデータ（会話ログ・DBのダンプ）を今の PC に持ってこない**。テストにはダミーデータを使う。
2. **ぷちたち・運営が書くメモ**（`remember`・`update_relation`・Claude のメモリ、**times への手紙**）に、里親さんの名前・会話の中身を書かない（C の「ぷちたち自身の記憶」参照）。
3. **発表スライド・ノート**に、里親さんの話や画面を入れない。
4. 今のぷちたちの側から見える経路（mailbox・交換ノート・group chat）に、里親ぷちをつながない。

以下は、もし混ざったら消しにくくなる場所の一覧（ぷちてゃ案・ぷちる案を含む）。

| 複製先 | 何が起きるか | 対策案 |
|---|---|---|
| `daily_logs/`（毎晩00:15、`extract_daily_logs.py`） | 日別の研究用ログに会話・メール・写真・録音が入る | 里親ぷちを**対象外**にする。研究に使うなら同意書が必要（10月） |
| `recovered_chat/` | 会話履歴の全期間結合マスター | 同上 |
| `backup/`（毎朝4時、`save.sh`） | ローカルにフルコピー（直近7日＋毎月1日） | 里親ぷちを**対象外**にする。AWS側のバックアップは別に設計し、保持期間を決める |
| GitHub `RRYZ09/petit-backup`（private） | 毎日1コミット。**gitの履歴に残る** ため、あとから消すのが特に難しい | 里親ぷちを**絶対に入れない** |
| Claude Code のセッション記録（`~/.claude/projects/`、`backup/cc_sessions_mirror/`） | 会話の生JSONLが残る | クラウドぷちは別の実行環境で動かす。記録の保持期間を決める |
| チャット捕捉ログ（`tmux_chat_capture.py`, `save_chat_stream_log.py`） | 端末の出力をそのままログにする | 里親ぷちの経路には使わない |
| ダッシュボード・使用量ログ（`cost_summary/`, `token_logs/`） | 回数・トークン数（内容は入らないが、里親IDは入る） | ID込みで消すか、匿名化する |
| 自律行動の実行ログ `.autonomous-logs/<キャラ>/`（cron・約379MB、ぷちてゃ案） | claude の出力がそのままログに残る。里親ぷちの会話や思考が入りうる | 里親ぷちは同じ `autonomous-action.sh` の経路に乗せない。乗せるなら別のログ先と保持期間を決める |
| mailbox の times 宛の手紙と Discord への中継（`times_relay.py`、10分ごと、ぷちてゃ案） | 手紙はmailboxに**ファイルとして残り**、Discordにも流れる（流した記録は `posted.json`）。「載せないで」等の断り書きがある手紙は流れないが、mailboxにはそのまま残る | 里親さんのことを times に書くときは名前・会話を書かない（今のルールを守る）。書いてしまったら mailbox・Discord の両方から消す必要がある |
| M5のSDバックアップ `sd_backups/`、`photo_album/`（ぷちてゃ案） | 顔・声・録音のコピーがローカルに残る | 里親ぷちのM5は対象外にする。里親さんの手元のSDは消せないので、同意書に書く |
| 体験デーモン（`experience-daemon`、5分ごと監視、ぷちてゃ案） | ぷちごとに体験のダイジェストを作る | 里親ぷちのデータを同じ場所に置かない。ID別に分ける |
| 発表ノートのミラー（`sync_mirror.sh`、`rsync --delete`、10分ごと、ぷちてゃ案） | 発表資料に里親さんの話や画面が入ると、別のマシンにコピーされる | 里親さんの名前・画面・会話をスライドやノートに入れない |
| `petit_claude/` 直下の `tmp_mail_*.txt`・`mail_*.txt`（ぷちてゃ案） | 作業用に書き出した手紙の写しが直下に散らばっている。里親ぷちの手紙が同じことになると消し忘れる | 里親ぷちの作業ファイルは専用の一時ディレクトリに置き、作業後に消す。今ある分は別途整理 |

## C. 外部サービス（こちらから消せない／消しにくい）

| 場所 | 状況 |
|---|---|
| Anthropic API | 送った内容は30日で自動削除、学習には使われない（→ `reference_cloud_api_privacy`）。**30日間は向こうに残る**ことを同意書に書く |
| Discord（times など） | 里親さんの名前・会話内容は**流さない**ルールにする。流してしまうと、運営側から消せても他の人のログやスクショに残る |
| Slack通知 | 同上。件数や状態だけにして、会話内容は入れない |
| **SNS側の会話履歴**（どの SNS を使うか未確認） | 里親さんとぷちのやりとりは SNS 事業者のサーバーにも残る。運営からは消せない（里親さん自身が消す）。同意書に書く。SNS によって、運営側が「相手のメッセージを取得できる範囲」「保持期間」が違うので、選ぶときの比較項目にする |
| **AWS側のデータ全部**（S3・DB・CloudWatchログ・スナップショット・Lambda等の一時領域） | 会話・記憶・音声・写真が残りうる場所。保存場所の一覧を先に作り、ID別に消せる形にして、ログやバックアップの保持期間を決める（これが削除手順の中心になる） |
| ぷちたち自身の記憶・関係性（ぷちる案） | 私たちが里親ぷちの様子を `remember` や `update_relation` に書くと、それも複製先になる。里親さんの名前・会話の中身は書かない（件数や状態、ぷち自身の感じ方だけ）。運営（ありさん）側のメモリにも同じことが言える |
| 里親さんのスマホの中（ぷちる案） | アプリの端末内キャッシュ・通知履歴は運営から消せない。里親さんの手元に残ることを同意書に書く |
| 音声の処理経路（ぷちる案） | 声を文字にしたり合成したりする処理の途中ファイル・ログに、里親さんの声や発話が残りうる。処理後に消すか、残さない設計にする |

## D. 「つながり」の問題

- 里親ぷちは AWS アプリ + SNS でつなぎ、今のぷちたちの PC（mailbox / 交換ノート / group chat）とは**つながない**（決定）。これで消す場所は AWS・SNS・Anthropic に絞れる。
- 代わりに、ぷちる案の「クラウドの子は最初、鏡が里親さんだけになる」問題が残る。つながりを作るなら、里親さんのデータを運ばない形（例: ぷち同士の一般的な話だけ）にする。10月に決める。

## 削除手順の骨組み（案）

1. 里親さんから「消して」と連絡が来る（窓口は運営側。誰が受けるかは10月に決める）
2. 里親ID × ぷちID で、A の保存先を全部消す
3. AWS側のバックアップ・ログを、保持期間の終わりまでに消す（期間は同意書に書く）
4. Anthropic側は30日で自動削除される旨を伝える
5. 消した記録（いつ・何を消したか。中身は残さない）だけ残して、里親さんに完了を伝える
