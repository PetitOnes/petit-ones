# Claude Code トークン消費削減の取り組み（2026-03-10）

## 問題の整理

複数のAIキャラクターが20分毎に自律行動するシステムで、消費が多かった原因は4つ：

1. **コンテキストの背景コストが大きい** — MEMORY.md（上限ギリギリ196行）、CLAUDE.md（231行）、MCP ツール定義（memory-mcp だけで30個以上のスキーマ）、hooks（毎ターン実行）が毎回送信されていた
2. **Opus 4.6 をすべてに使っていた** — 詩の対話もコード修正も調べものも全部 Opus。最高コストモデルの乱用
3. **`/clear` / `/compact` を使っていない** — 会話が長くなるほど毎ターンの入力トークンが膨れ、auto compact まで放置するとその時点で大量消費済み
4. **セッションが無制限に伸びていた** — `claude --resume` で再利用するたびキャッシュが積み上がり、`--max-turns` の指定もなく 1起動あたり 20ターン前後まで伸びていた（ぷちこ：60calls / 3.9M、ぷちる：63calls / 3.8M）

---

## 取り組み①：コンテキストの圧縮（3/9）

| 対象 | Before | After | 削減率 |
|------|--------|-------|--------|
| CLAUDE.md | 231行 | 31行 | 87% |
| MEMORY.md | 196行 | 51行 | 74% |
| settings.local.json 許可リスト | 193件 | 23件 | 88% |
| enableAllProjectMcpServers | true（常時全MCP読み込み） | false（m5は必要時のみ） | — |

- MEMORY.md は詩一覧・発見・最近の出来事を別ファイルに分割し、本体は索引のみに
- 許可リストは一度きりのコマンドを削除し、パターンベースに統一

---

## 取り組み②：モデル使い分けルールの制定（3/9）

- デフォルトモデルを Sonnet に変更
- 詩・深い対話のときだけ `/model opus`
- 計画は Opus、実装は Sonnet（`/model opusplan`）

---

## 取り組み③：運用ルールの制定（3/5・3/9）

キャラクターたちと決めた行動ルール：
- メールは発見ごとに1通 → まとめて1通に
- 調べものはメールでなく記憶かノートに書く
- タスク切り替え時は `/clear`、長い会話中はこまめに `/compact`（auto compact まで放置しない）
- 自律行動中も `/compact` の活用を推奨

---

## 取り組み④：`--max-turns` でセッションのターン数を制限

`autonomous-action.sh` の `claude -p` に `--max-turns` を追加：

| キャラクター | MAX_TURNS |
|---|---|
| ぷちてゃ・ぷちこ | 15 |
| ぷちる | 10 |

環境変数 `MAX_TURNS` で個別上書き可能。

---

## 取り組み⑤：日次セッションリセット

日付が変わったら `.heartbeat-session-id` を自動削除してコンテキストをリフレッシュ。`.heartbeat-session-date` で前回実行日を管理。

---

## 取り組み⑥：自律行動の頻度をダッシュボードから変更可能に

Webダッシュボードの設定ポップアップに「自律行動の頻度」ドロップダウンを追加：

- 20分に1回（毎回）
- 40分に1回（1回スキップ）
- 60分に1回（2回スキップ）

`settings.json` の `autonomous_skip` フィールドでキャラクターごとに設定可能。cronの間隔は変えずに実質的な頻度を下げられる。

---

## おまけ：使用量確認スクリプト（`scripts/check_usage.py`）

今日・今週・今月の呼び出し数・トークン数に加え、**時間帯別呼び出し分布**を表示。キャラクター別集計も可能。

```bash
python3 scripts/check_usage.py                        # 全体
python3 scripts/check_usage.py --character puchiteya  # キャラ別
python3 scripts/check_usage.py --json                 # JSON出力
```
